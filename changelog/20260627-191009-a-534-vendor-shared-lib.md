## Added

- **Canonical `lib/` vendored into each bundle, with a CI drift-check ([R-534](https://linear.app/rheged-studio/issue/R-534)).**
  Shared logic that several bundles need can't be a runtime import — bundles must
  stay independently installable (zero cross-bundle imports) — so it was hand-copied
  and drifted. [ADR-0004](architecture/0004-shared-lib-vendor-convention.md) settles
  the mechanism: one editable source per helper under a repo-root `lib/`
  (zero-dependency, Node built-ins only), which `pnpm vendor:sync` stamps into each consumer's
  `scripts/lib/vendor/` behind a generated do-not-edit banner. `pnpm vendor:check`
  (a new `🧬 Vendor drift-check` step in CI's `build-and-lint`) fails the build if any
  vendored copy drifts from its canonical source. The sync tool
  (`infrastructure/scripts/vendor-sync.mjs`) carries a manifest, a `--check` gate, and
  a `--self-test`, with vitest cover over its pure core. `lib/` is kept out of the
  published `files: ["skills/"]` surface — only the vendored copies (inside each
  bundle) ship, so independent installability holds.

## Changed

- **First two helpers migrated onto the vendored lib.** The issue-key regex builder
  (`lib/issue-keys.mjs`, `buildIssueRe`) is vendored into the `changelog` bundle —
  `add-links.mjs` now imports it instead of inlining `ISSUE_RE` — and `linear-sync`
  and `cleanup-repo` point their prose at the canonical module (closing the loop on
  the deferral noted in [R-539](https://linear.app/rheged-studio/issue/R-539)).
  `detectBaseBranch` (`lib/base-branch.mjs`) is vendored into `preflight` and
  `initialise-skills`, whose `scope.mjs` / `git.mjs` re-export it — preserving their
  public signatures and existing tests — and the old "keep in sync" comments are gone.
  Bundled as `changelog@0.6.1`, `linear-sync@0.3.2`, `cleanup-repo@0.3.2`,
  `preflight@0.1.7`, and `initialise-skills@0.4.1`.
