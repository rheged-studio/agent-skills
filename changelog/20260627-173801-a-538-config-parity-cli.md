## Added

- **Config/example key-parity check ([R-538](https://linear.app/rheged-studio/issue/R-538)).**
  `pnpm validate:skills` now asserts that any `skills/<name>/` shipping **both**
  `config.json` and `config.example.json` keeps their key sets identical
  (recursively; values may differ — the example carries placeholders). A key in one
  but not the other means an adopter copying the template silently gets a stale or
  incomplete config. Skills shipping only one file (e.g. `preflight`) are exempt.
  This caught a real divergence in `send-it`, now reconciled (`config.json` and
  `config.example.json` share one key set). Bundled as `send-it@0.3.4`.
- **`review-threads.mjs` gains `--help` ([R-538](https://linear.app/rheged-studio/issue/R-538)).**
  The triage-pr review-thread fetcher was the last user-facing bundled script
  without a `--help` flag; it now prints usage and exits before fetching.
  (`classify-lint.mjs` is an internal module with no CLI entrypoint, so it stays
  exempt.) Bundled as `triage-pr@0.4.2`.

## Changed

- **Documented the trunk-key naming ([R-538](https://linear.app/rheged-studio/issue/R-538)).**
  The diff-based skills name the trunk `baseBranch` (`changelog`, `send-it`) while
  `cleanup-repo` names its merge-detection target `mainBranch`; CLAUDE.md now records
  that the divergence is intentional (`initialise-skills` maps between them), so
  neither is "fixed" to match the other.
