## Added

- **`stats.commits` on the changelog rail ([R-560](https://linear.app/rheged-studio/issue/R-560)).**
  The post-merge enrichment step now resolves a `commits` count for each entry and writes it
  under `stats`, alongside `files_changed` / `loc_added` / `loc_removed`. The count comes from
  the GitHub PR commits API (`repos/{owner}/{repo}/pulls/<n>/commits`), which still returns a
  PR's original commits after a squash-merge collapses them on `main` — so the number is
  recoverable and recorded durably. **Merge commits are excluded** (commits with more than one
  parent — typically `main`-merge resolutions on the branch), so the count reflects authored
  work rather than branch upkeep. A new zero-dep `lib/commit-count.mjs` holds the resolver
  (runner-injectable, so it's unit-tested offline); `finalise-changelog.mjs` and `lib/enrich.mjs`
  thread it through, and the count is resolved independently so a commits-API hiccup never
  discards the other stats. The validator and the changelog contract gain the new optional field.

- **Backfilled the existing changelog backlog, and a `backfill-commits.mjs` to do it elsewhere.**
  Every existing `changelog/` entry whose merged PR resolves now carries its `stats.commits`
  value. The backfill splices in only the `commits` line (no frontmatter re-serialise), so each
  entry's diff is a single added line; it's idempotent and best-effort per entry. Scoped to this
  repo for now — rolling the backfill out to the other served repos is a deferred follow-up.
