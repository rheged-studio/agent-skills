# ADR-0006: Shared reference prose is vendored like shared code

- **Status:** Accepted
- **Date:** 2026-10-12
- **Tracking:** [R-1203](https://linear.app/rheged-studio/issue/R-1203)
- **Supersedes:** —
- **Superseded by:** —
- **Extends:** [ADR-0004](0004-shared-lib-vendor-convention.md)

## Context

ADR-0004 settled how **code** is shared between independently installable skill
bundles: one canonical `lib/<file>.mjs`, copied into each consumer by
`pnpm vendor:sync`, with a CI drift-check. It said nothing about **prose**.

R-1203 needs the same rule text in three bundles. The lint-surface gate ("config
edits and ignore directives are a developer decision") was written for `triage-pr`
(R-1182) and has to apply in `preflight` and `commit` as well. The options were the
same ones ADR-0004 weighed for code, with the same outcomes:

- **Restate it in each skill.** Three hand-maintained copies that drift. This is the
  failure ADR-0004 exists to stop.
- **Link from the other skills into `triage-pr`'s reference file.** That is a
  cross-bundle dependency: the link dangles in any consumer that installs `preflight`
  or `commit` without `triage-pr`.

## Decision

**Shared reference prose follows ADR-0004's mechanism unchanged, with a markdown
banner and a `references/` destination.**

- **Canonical source:** a markdown file under the repo-root `lib/`, e.g.
  `lib/lint-surfaces.md`. Like the `.mjs` modules, `lib/` is not published; only the
  vendored copies under `skills/` ship.
- **Write it bundle-neutral.** The canonical file states the rule; each skill's
  `SKILL.md` (or its own references) says where that skill applies it, such as its
  natural stopping point, its report, or its envelope. Skill-specific steps don't go in
  the shared file.
- **Destination:** `skills/<name>/references/<file>.md`, next to the bundle's other
  reference docs, so `SKILL.md` links it with a plain relative link
  (`references/lint-surfaces.md`).
- **Banner:** `vendor-sync.mjs` picks the banner by extension. Markdown gets an HTML
  comment (`` <!-- @generated by `pnpm vendor:sync` … DO NOT EDIT … --> ``) so the notice
  never renders as visible prose; `.mjs` keeps the `//` banner. The shared
  markdownlint config already disables MD041, so a comment before the first heading
  lints clean.
- **Drift-check and versioning:** the same as ADR-0004. A manifest row maps the
  source to its destinations, `pnpm vendor:check` fails CI on a missing or edited
  copy, and a sync that changes a copy is a bundle edit with a hand-bumped version.

## Consequences

- **First use (R-1203):** `lib/lint-surfaces.md` is vendored into `triage-pr`,
  `preflight` and `commit`. `triage-pr`'s `review-discipline.md` keeps its section
  heading, so existing anchors resolve, but now points at the vendored copy and keeps
  only its own stopping-point and unattended-path rules.
- **Adding shared prose** is the ADR-0004 recipe with a `.md` source: write
  `lib/<file>.md`, add a manifest row, run `pnpm vendor:sync`, bump the touched
  bundles.
- **Edit the source, never the copy.** A vendored reference file is generated; a
  hand edit to it fails `pnpm vendor:check`.
